# Conversio Target Coverage Matrix

**Rendered** by `faber/scripta/render-matrices.py` from `radix/corpus/measurement/conversio/*.json` (emitted by the private radix ladder) — **do not hand-edit**.
**Measurement**: `emit_conversio_target_matrix` over the type-family cartesian product. Fixture-backed cells are **measured** (real frontend + real MIR probe + real HIR emit-arm detection, no external toolchains); the rest are classifier predictions.

This is the **official generated** conversio (`↦`) coverage matrix. It reports, per (type-family × type-family × target), whether a conversion has a **dedicated lowering** (✓), is accepted but **only via the unspecialized fallback** (◐ — not guaranteed to compile), is **semantically rejected** (✕), or is **not emitted by the target** (—).

## Legend

| Glyph | Tier | Meaning |
|---|---|---|
| ✓ | dedicated | the target has a dedicated lowering arm for this pair |
| ◐ | fallback | semantic-accepted, but only the unspecialized fallback (may not compile) |
| ✕ | rejected | the typechecker denies the pair before any backend |
| — | not emitted | the target cannot lower this pair |

> Tier precedence per cell: `✕ rejected > — not emitted > ✓ dedicated > ◐ fallback`. `✕` is target-independent (it mirrors the semantic `↦` policy). The `◐` tier is specific to HIR backends with an unspecialized fallback (notably Rust's `emit_unspecialized_conversio_target`); MIR targets lower `↦` to a runtime intrinsic the runtime owns and have no `◐` tier.

## Provenance

**441** of 441 cells are **fixture-backed and measured** (an authored `examples/conversio-matrix/<src>/<tgt>.fab` exists and the harness measured its real frontend / MIR / emit-arm verdict) and rendered in **bold**. Plain glyphs are classifier predictions (no fixture yet).

> Honesty note: measured verdicts come from the real compiler pipeline (`✕` from `analyze_source` with the issue code captured, MIR `✓`/`—` from `classify_mir_coverage` on the lowered fixture, HIR `✓`/`◐` from emit-arm detection in each backend). The read-only classifier remains as a cross-check oracle; cells where the measured verdict disagrees with the prediction are listed under Measured divergences.

## Regeneration

The measurement JSON is regenerated by the private radix ladder (`./scripta/test --full` / `--release`, stage-4 measurement gates) via `scripta/emit-compat-json.py` and committed at radix release. Render:

```bash
python3 scripta/render-matrices.py          # render in place
python3 scripta/render-matrices.py --check  # fail if committed docs are stale
```

Rerun whenever the conversio codegen, semantic `↦` policy, or MIR lowering changes.

## Family-level granularity notes

- Each aggregate family (`tensor`, `vector`, `matrix`, `sparsa`, `intervallum`) collapses shape/element variance into one cell.
- `valor ↦ fractus<f32>` (sized) is semantically rejected; `valor ↦ fractus` (unsized) is dedicated. The `fractus` family cell reports the unconditional (unsized) verdict.
- `tensor ↦ tensor` reports dedicated when element widths unify; shape or element mismatch is a conditional rejection, not a cell verdict.
