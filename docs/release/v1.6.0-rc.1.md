## Purpose

Release-candidate lock for the reproducible Stage 7 archive gate. This
candidate does not add product surface: it pins the companion revisions,
refreshes `Cargo.lock`, proves the locked release build from the pin, and
packages the RC archive (faber binary + the MLP and BERT-tiny compiled
packages) with a basename-only SHA-256.

N1.2: faber binary + the MLP and BERT-tiny compiled packages, backend blobs
[Metal MSL, CUDA PTX] inside the package images). The package images
(`packages/*/image.fmir`) are **byte-identical across targets** — one

## Demonstrated capability (E6/E7 receipts — the exact claim level)

Device execution and package rows at **RC level, machine-scoped**. The four
Stage 7 receipts are the evidence; no claim below exceeds them:

| Machine | Backend / device | E6 (RC binary) | E7 (clean-room extracted archive) | Receipts |
| --- | --- | --- | --- | --- |
| **burgus** | Metal — Apple M5 Max, Metal 4, macOS 26.5.2 | MLP + BERT-tiny via `faber run --backend metal .`, exit 0 | MLP + BERT-tiny via `__fmir-run image.fmir --backend metal`, exit 0 (temp home, `PATH=/usr/bin:/bin`, `FABER_LIBRARY_HOME` unset) | `stage-7-evidence-burgus-metal-e6.md` (U2) / `-e7.md` (U4) |
| **pharos** | CUDA — NVIDIA RTX 5070, driver 595.71.05, CUDA 13.2, Ubuntu 24.04 | MLP + BERT-tiny via `faber run --backend cuda .`, exit 0 | MLP + BERT-tiny via `__fmir-run image.fmir --backend cuda`, exit 0; execve audit: zero compiler invocations (driver JIT via `cuModuleLoadData`) | `stage-7-evidence-pharos-cuda-e6.md` (U3) / `-e7.md` (U5) |

- Every numeric-policy v1.0.0 row PASS on all four runs vs the pinned oracles
  (mlp: loss worst `1.318e-07`, convergence ratio `0.01137 < 0.1`; bert-tiny:
  loss worst `2.641e-07`, 18/18 observed gradients and 18/18 final params in
  bound); all observed values finite; leak-free teardown
  (`live_handle_count()=0`); observation-only readback.
- **Honest PTX delta (recorded, `stage-7-evidence-pharos-cuda-e7.md` §9):** the
  RC archive's compiled CUDA images embed the canonical Stage 0 payload
  (`ptx87`, `.version 8.7` / `.target sm_90`, JIT-compiled by the driver at
  module load); the E6 source-package route recompiled at runtime to ptx 7.8.
  The backend-neutral A10 identity, execution-descriptor hashes
  (mlp `25181bd996f0173b`, bert `8edaeb79dd548ffb`), and device trajectories
  are byte-identical across both routes. The burgus E6↔E7 device output is
  byte-identical (module hashes included).
- Device-observability caveats carried forward honestly: `ln1`/`attn`/
  `context`/`ln2` and the softmax row sums are not in the declared EndOfRun
  forward set (recorded as not-device-observed, not PASS); the frozen-slot
  gradients (`input`/`dk_scale`/`target`) are excluded from the EndOfRun
  readback.
- **Capability rows**: `faber targets` for `metal-text` / `llvm-text` report
  `run=yes` and `package=yes` at RC level on the named machines (RC-local);
  `-t metal-text` / `-t llvm-text` remain emit-only (A6). Updated together
  (N1.8): `targets.rs`, `radix/docs/design/target-capability-matrix.md`, radix
  & faber READMEs, examples index + package docs, these notes, `$faber` skill.
