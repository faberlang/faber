## Purpose

Release-candidate lock for the reproducible Stage 7 archive gate. This
candidate does not add product surface: it pins the companion revisions,
refreshes `Cargo.lock`, proves the locked release build from the pin, and
packages the RC archive (faber binary + the MLP and BERT-tiny compiled
packages) with a basename-only SHA-256.

## Pin pair (stage-6 residual 3 resolved)

The candidate pins faber `6dbda59` against radix `4792fcf6`. Faber has
adopted the renamed radix API (`Target::Rust` → `HirRust`, `radix::tool`
postprocess renames — `844c4de`, `5f0f95c`), so current faber main pairs with
current radix main; the `--locked` release build from the pin is the proof
(`v1.6.0-rc.1-sibling-pins.md`). Companion pins: faber-runtime
`10d48ea`, hosts `e066ee0a`, cista `93552882`, gradus `24e54989`, examples
`aad199ec`.

## Archive

Per-target archives (single archive per target per `release-manifest.yaml` /
N1.2: faber binary + the MLP and BERT-tiny compiled packages, backend blobs
[Metal MSL, CUDA PTX] inside the package images). The package images
(`packages/*/image.fmir`) are **byte-identical across targets** — one
canonical FMIR semantic identity; only the launcher binary differs per target.

Both archives + basename-only `.sha256` live under `dist/`. The Linux archive
was added as the CTO-5 follow-up so pharos (Linux x86_64 CUDA) can prove the
launcher (TR7-U3/U5): same pinned tree as TR7-U1, built in an amd64
`ubuntu:24.04` container (glibc 2.39 — matches pharos) with rustc 1.97.1
(identical release to the macOS build); per-target hashes in
`v1.6.0-rc.1-sibling-pins.md`.
