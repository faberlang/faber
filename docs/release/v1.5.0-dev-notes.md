> **Status**: development track — NOT a released tag. These notes record the
> capability-promotion surface for the differentiable-GPU campaign

## Device execution (Metal / CUDA) — capability promotion (N1.8)

The ordinary-command gate (E5) passed for one proven collection kernel (a tree
reduction, `summa`) on both named machines, so the Metal/CUDA capability rows
flip **now** per the frozen promotion policy (architecture record §8, N1.8):

| Row | before | after | why |
| --- | --- | --- | --- |
| `metal-text` run | no | **yes** | `faber run --backend metal` executes device programs on Apple M5 Max (burgus) |
| `llvm-text` run | no | **yes** | `faber run --backend cuda` executes device programs on NVIDIA RTX 5070 (pharos), NVVM→PTX device artifacts |
| `metal-text` / `llvm-text` package | no | no | `package=yes` waits for the Stage 7 archive gate (E6/E7) |

The `-t metal-text` / `-t llvm-text` emit surfaces are unchanged (A6);
device execution is selected by `faber run --backend <metal|cuda>`.

## New ordinary-command surface

- `faber run --backend <auto|metal|cuda>` + `[device] backend` manifest key
  (S1-5).
- `[device] inputs` manifest key: host input values for the package's
  device-program input buffers (S1-6 vertical slice).
- Device-capable packages carry an `@ nucleum` compute kernel; the packaged
  FMIR image's `device` section carries the canonical device program, the
  MSL/PTX artifacts (provenance hashes), the selection request, and the
  `device:*` runtime requirements.
- Fail-before-launch on real drivers with stable structured codes:
  `E_BACKEND_UNAVAILABLE`, `E_NO_DEVICE_PROGRAM`, `E_DEVICE_DESCRIPTOR`,
  `E_DEVICE_ABI_MISMATCH`, `E_DEVICE_ENTRY_MISMATCH`, `E_DEVICE_DTYPE_MISMATCH`,
  `E_DEVICE_SHAPE_MISMATCH`.

## Proof

`examples/training/device-summa` — one tree-reduction kernel through the
device program → packaged FMIR image → composite host → real Metal/CUDA
sessions. Numeric parity vs the pinned CPU oracle (numeric-policy v1.0.0,
reduction-sum row) with an exact match on both backends.

## Not yet (Stage 7+)

  `faber targets`/matrix `package` column.
- Multi-kernel device programs, persistent training-step lifecycle (Stage 2).
