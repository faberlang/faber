# Faber v1.5.1

> **Status**: final — patch (hotfix channel) on the `1.x` line; prepared on
> `release/faber-1.5.1` cut from the `v1.5.0` source tag (`5d7a3e5`).

Packaging patch release fixing the **P0 public-release defect in v1.5.0**:
the v1.5.0 release archive shipped a **bare binary** (`faber` + `README.txt`),
so a fresh install failed closed with no pack source (`failed to load default
code locale 'en' pack …/share/faber/locale/en/pack.toml`). The v1.5.1
archives ship the **assembled dev-kit tree** — packs beside the binary, which
the v1.5.0+ runtime already resolves. The missing consumer smoke test (fresh
install of the published artifact → `faber check --locale en` on a
hello-world → works) becomes a hard release gate.

## What ships in the 1.5.1 archive

`faber-v1.5.1-<triple>.tar.gz` extracts to `faber-v1.5.1-<triple>/`:

```
bin/faber                         # launcher
share/faber/reference/            # reference pack (index.toml, PACK.toml,
                                  #   legacy-redirects.toml, exempla/)
share/faber/locale/<8>/pack.toml  # reader packs (ar, en, hi, la, th-TH,
                                  #   vi, zh-Hans, zh-Hant)
```

plus a basename-only `.sha256`. A fresh install (clean prefix, fresh HOME,
minimal PATH, no siblings) yields `faber --version` = 1.5.1, `faber check
--locale en <hello-world>` exit 0, and `faber explain SEM001` exit 0.

## The consumer smoke gate (new)

`scripta/smoke-test-release-archive` installs the published archive into a
clean prefix and exercises the packs **before** the version assertion, so a
v1.5.0-shaped bare-binary archive is rejected by the fail-closed pack error
(`--expect-fail-class pack-error`) — never by a version mismatch. The gate is
wired into the release process docs, CI packaging, and the authoritative
readback step; promotion is blocked until it is green on the downloaded
public bytes.

## Supersede note (hotfix protocol, `release-runbook.md` §2.7 / §4)

v1.5.1 **supersedes v1.5.0 in discovery**. It is a new patch release — there
is no in-place replacement: the v1.5.0 tag and its stable archive bytes remain
immutable and untouched. Site/installer/`Latest` metadata moves to 1.5.1 only
after the release passes all gates and remote readback
(`release-contract.md` §4.3).
