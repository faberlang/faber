## (b) `manifest_build_target` allowed-target list — no `"wasm"`

Source: `faber/src/package/manifest.rs` (lines 346–369). The allowed-target match:

```rust
pub(crate) fn manifest_build_target(
    target: Option<&str>,
    path: &Path,
) -> Result<Target, Box<Diagnostic>> {
    match target.map(str::trim) {
        None => Ok(Target::HirFhir),
        Some("rust") => Ok(Target::HirRust),
        Some("fhir") => Ok(Target::HirFhir),
        Some("ts") | Some("typescript") => Ok(Target::HirTypeScript),
        Some("scena") => Ok(Target::MirScena),
        Some("fmir-text") => Ok(Target::MirFmir),
        Some("fmir") => Ok(Target::MirFmirBinary),
        Some("fmir-bin") => Ok(Target::MirFmirBundle),
        Some("llvm-host") => Ok(Target::MirLlvmHost),
        Some(unsupported) => Err(Box::new(
            crate::package_diagnostic_error(format!(
                "faber.toml build.target '{unsupported}' is not supported for package builds"
            ))
            ...
        )),
    }
}
```

There is **no `"wasm"` arm**. The same function gates library `[build] targets` lists via `validate_library_build`, so `build.kind = "lib"` + `build.targets = ["wasm", …]` rejects identically.

Live rejection probe — `faber.toml` declaring `[build] target = "wasm"` (bin package, entry set), CLI run without `--target`:

```toml
[package]
name = "importa-wasm"
version = "0.1.0"
edition = "2026"

[paths]
entry = "main.fab"

[build]
target = "wasm"
kind = "bin"
```

```text
$ faber build --package .
error: faber.toml build.target 'wasm' is not supported for package builds
EXIT=1
```

So the **CLI** `--target wasm` package route is live (a) while the **manifest** surface has no `"wasm"` spelling — the manifest rejects the row the campaign's Stage 3 gate requires. This asymmetry is recorded here and named for U3's target-conflict-ledger (`manifest_build_target` rejects `[build] target = "wasm"` while CLI `--target wasm` works).

## (d) Gap list — CAMPAIGN "locked source-library closure is incomplete" row

CAMPAIGN.md §Current Tracks row (verbatim):

> | Faber Wasm packages | package-aware builder persists WAT and retains binary modules in memory; locked source-library closure is incomplete | persist deterministic binary modules, close target-native libraries, and expose a browser-app recipe |

Exact gap list (each with live authority):

1. **No persisted binary module set.** Only `.wat` is written under `<pkg>/target/faber/wasm/`; `.wasm` bytes exist only in-memory (`manifest.entry_bytes` / `sibling_bytes`). Authority: `src/package/wasm.rs` (`build_package_wasm_from_graph`), the CLI probe's `find target -type f` → two `.wat`, zero `.wasm`, and the reserved `binary_path` doc comment.
2. **No Norma/library closure through the wasm target.** `plan_wasm_artifacts` (`src/package/artifact_plan.rs`) emits only package units as module nodes — no `GeneratedLibrary` / lock-index handling (contrast `plan_rust_artifacts`' `linked_library_crates`); the builder consumes the package graph from `analyze_package` only (`src/package/wasm.rs` INVARIANT). Locked deps (`faber.lock`) and Norma source are not closed into the wasm module set.
3. **No browser product recipe.** `faber build --target wasm` stops at the module set and prints the output dir (`src/package/cmd.rs` wasm dispatch); `[product]` has only `BrowserApp`/`TypeScript` today (`src/package/manifest.rs`). No serve UX, no browser distribution.
4. **No `faber.toml [build] target = "wasm"` row.** `manifest_build_target` has no `"wasm"` arm and rejects it live (b). The CAMPAIGN §Stage 3 gate ("the normal command uses external target `wasm` for a browser-app product") requires this row to exist.
5. **Stale `faber targets` capability claim.** The `wasm` row reports `run=no package=no` ("not faber run/package") while the live CLI probe builds wasm packages (a). Named for U3's target-conflict-ledger; not reconciled here.

**Stage 3 durable output** (per CAMPAIGN §Stage 0 gate and §Stage 3): a deterministic binary module set + manifest that replaces this limitation — persist real `.wasm` modules under a deterministic name scheme, close locked source-library dependencies through the wasm target, and dispatch a browser wasm product before the generic wasm package fallback.
