# Goal: Core-Support Cache Must Bundle Radix Runtime-Contract Crates

## Summary

`faber test` fails because the embedded core-support cache bundles `faber-runtime`
and `hosts/` but not the `radix/` sibling tree. The `faber-runtime` Cargo.toml
references `radix-runtime-contract` and `radix-host-abi` via relative path
dependencies (`../radix/crates/...`) that resolve correctly in the live
faberlang workspace but break inside the extracted cache.

## Problem

### What happens

```text
$ faber test src/triga_proba.fab

error: failed to get `radix-runtime-contract` as a dependency of package
`faber-runtime v0.1.0 (.../core-support/tar-zst-v1/<hash>/faber-runtime)`
...
Caused by: failed to read
`.../core-support/tar-zst-v1/<hash>/radix/crates/radix-runtime-contract/Cargo.toml`
Caused by: No such file or directory (os error 2)
```

### Root cause

`faber-runtime/Cargo.toml` (the source of truth at
`faberlang/faber-runtime/Cargo.toml`) declares:

```toml
[dependencies]
radix-runtime-contract = { path = "../radix/crates/radix-runtime-contract" }

[dev-dependencies]
radix-host-abi = { path = "../radix/crates/radix-host-abi" }
```

These paths resolve in the live faberlang container:

```text
faberlang/
  faber-runtime/Cargo.toml          ← depends on ../radix/crates/...
  radix/crates/radix-runtime-contract/  ← exists
```

But the core-support archive (`faber/core-support-manifest.txt`) bundles only:

```text
faber-runtime
hosts/crates/host-kernel
hosts/crates/host-native
hosts/crates/aleator
hosts/crates/http
hosts/crates/consolum
hosts/crates/processus
hosts/crates/solum
hosts/crates/tempus
```

No `radix/` entry. When faber materializes the archive into the content-addressed
cache, the extracted tree is:

```text
core-support/tar-zst-v1/<hash>/
  faber-runtime/          ← bundled
  hosts/                  ← bundled
  # radix/                ← MISSING
```

The `../radix/crates/radix-runtime-contract` path dep resolves to
`core-support/tar-zst-v1/<hash>/radix/crates/radix-runtime-contract` — which
does not exist. Every `faber test` invocation hits this.

### Why this wasn't noticed before

`faber test` was never successfully used on a real package until now. The Triga
exempla used deprecated `adfirma` inside `incipit` blocks (parsed by `radix check`
but not run as tests). The first attempt to use `probandum`/`proba` + `faber test`
revealed this latent gap. This is not a regression — it is pre-existing.

## Evidence

### Cache contents (all entries, not just the current hash)

Verified across 30+ cache entries under
`~/Library/Caches/faber/core-support/tar-zst-v1/`. **None** contain a `radix/`
directory. All contain `faber-runtime/` and either `hosts/` or `host-*-rs/`.

### Generated Cargo.toml hardcodes the cache path

`triga/target/faber/Cargo.toml` (generated by `faber test`):

```toml
[dependencies]
faber = { package = "faber-runtime", path = ".../core-support/tar-zst-v1/<hash>/faber-runtime" }
```

Cargo follows that path, finds `faber-runtime/Cargo.toml`, reads its path deps,
and fails resolving `../radix/crates/radix-runtime-contract`.

### Deleting the cache does not help

`faber test` re-extracts the archive to the same content hash. The hash is
deterministic from the embedded archive content — clearing the cache and
retrying reproduces the identical tree with the identical gap.

## Constraints

- The two radix crates are small contract/ABI definition crates, not the full
  radix compiler. `radix-runtime-contract` and `radix-host-abi` are likely
  standalone enough to bundle without pulling the entire compiler tree.
- The core-support manifest is read at faber build time (`build.rs`) from
  `faber/core-support-manifest.txt` and embedded as a compressed tar archive.
- Any change to the manifest changes the archive hash, which invalidates all
  existing caches — expected and fine.

## Open Questions

1. **Bundle the two missing radix crates?** Add
   `radix/crates/radix-runtime-contract` and `radix/crates/radix-host-abi` to
   `faber/core-support-manifest.txt`. Simplest fix. Pulls two small contract
   crates into every faber install.

2. **Bundle the whole radix tree?** Add `radix` to the manifest. Heavier but
   avoids future missing-crate surprises if `faber-runtime` adds more radix
   path deps.

3. **Change `faber-runtime` to not use path deps into radix?** Publish the two
   contract crates, or vendor them into `faber-runtime`. Cleanest architecture
   but requires more work and may not match the faberlang container model.

4. **Rewrite path deps during materialization?** The faber materializer could
   detect `../radix/` path deps and rewrite them to point at a live radix
   checkout. Fragile and assumes the runtime always has a sibling radix tree.

## Reference Packet

Before investigating, inspect:

- `faber/core-support-manifest.txt` — the allowlist of bundled roots
- `faber/build.rs` — how the archive is assembled from the manifest
- `faber/src/core_support/materialize.rs` — how the archive is extracted and
  verified
- `faber-runtime/Cargo.toml` — the source of the path deps that don't resolve
- `radix/crates/radix-runtime-contract/Cargo.toml` — confirm the crate is
  standalone
- `radix/crates/radix-host-abi/Cargo.toml` — same
- `triga/target/faber/Cargo.toml` (generated) — the generated path that Cargo
  follows to the missing radix crates

## Verification

After the fix:

```bash
cd faberlang/triga
export RADIX_ROOT=faberlang/radix
export FABER_LIBRARY_HOME=faberlang
rm -rf target/faber
faber test src/triga_proba.fab
```

Should compile and run the three proba tests in `triga/src/triga_proba.fab`
without a `radix-runtime-contract` resolution error.
