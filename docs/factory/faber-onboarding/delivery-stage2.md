## Outcome

The faber product realizes the dev-kit payload contract accepted at Stage 1. The
first implementation slice is bounded to **packs + resolver + verify + manifest
instance**; everything the routing table assigned to faber stages 4/5/6/7/8 is
**staged and routed**, never silently omitted and never implemented here.

1. **Packs ship in a versioned dev-kit payload.** A faber-owned assembly script
   produces a deterministic payload staging directory containing the launcher
   (`bin/faber`), the reference pack (`share/faber/reference/`), and locale
   packs for all eight radix locale dirs (`share/faber/locale/<locale>/`),
   including `la` (G3 faber-side). Core support remains embedded in the binary
   and materialized to the platform cache (E12); the manifest records the
   materialization rule.
2. **Resolvers read the installed location and fail closed.** Installed
   binaries resolve the reference pack and locale packs from the install prefix
   relative to the running binary — never from the `CARGO_MANIFEST_DIR`-baked
   build path (E8) and never from ambient cwd/exe-parent walk-up (E5/G2). A
   missing or version-skewed pack produces a nonzero, actionable error naming
   the missing layer. G1/G2/G10 faber-side close.
3. **The dev-kit payload manifest is a realized section of the single release
   manifest schema.** `faber/release-manifest.yaml` (repo root) is generated by
   the assembly script with `pinnedInputs.source` (exact source commits) and
   `pinnedInputs.packs` rows (launcher, core-support, reference-pack,
   locale-packs, library-pack) carrying component / version / digest /
   compatibility / license / destination per `release-manifest-schema.md` §6.
   This is the **first instance** of the schema; the machine JSON schema and
   validator are `component-release-streamline` Stage 3 (interlock §8).
4. **A clean-room verify step proves the payload.** `verify-dev-kit` extracts
   the payload at an arbitrary prefix into a fresh HOME with minimal PATH and no
   sibling checkouts, then asserts `--version`, `faber explain SEM001`,
   `faber explain functio` (reference lookup), a `[reader] locale = "la"`
   package check, core-support materialization, and fail-closed behavior on
   tampered / version-skewed content. The verify step makes **no** no-Rust /
   portable-execution claim (E4/E10 discipline; that proof is
   `release-and-portable-default` + faber Stage 5).

**Staged, not implemented (each routed with owner in §6):** Stage 4 `faber
doctor`; Stage 5 first-hour init/check/run + default execution target (G4);
Stage 6 Norma platform availability (G5 faber-side); Stage 7 Triga/third-party
acquisition (G5 faber-side); Stage 8 CLI locale docs/parity (G6/G10 faber-side)
+ faberlang.dev site parity; Stage 10 continuous-honesty CI (G11, wiring
`verify-dev-kit` into recurring clean-room CI); the cista need (verified
release-asset / exact-revision install pins, interface-only installs not probing
rustc — G5, routed to cista).

**Gate check (CAMPAIGN Stage 2):** extracting the payload at an arbitrary
prefix supports `faber --version`, reference lookup, and locale lookup without
siblings or environment overrides. Tampered or version-skewed content fails
before use. Payload construction has an early clean-room proof — the **local**
`verify-dev-kit` in this slice; the recurring CI proof is Stage 10.

## risks

- **Onboarding/streamline payload interlock (primary):** the manifest instance
  must match `release-manifest-schema.md` §3/§4/§6 exactly — component, version,
  digest, compatibility, license, destination per pack row. The machine JSON
  schema + validator land in streamline Stage 3; until then the instance
  validates against the documented shape and is re-validated when the machine
  schema lands (interlock §8). Streamline Stage 3 `package-archive` will wrap
  this staging directory; the layout here is the contract for that wrapping.
- **`release-and-portable-default` interlock:** that delivery is still in
  planning; the verify script must not claim no-Rust or portable execution
  (E4/E10). The released init target (gate decision 3) is staged to faber Stage
  5; this slice changes no execution default.
- **E5 false-green regression:** the resolver change must be proven with a
  hermetic-dir negative test containing a stray sibling checkout. Locally built
  binaries bake local paths — proof uses a release-shaped binary or the
  equivalent hermetic setup.
- **Reader-pack layout rename:** released v1.4.0 used `radix/stdlib/reader/la`,
  main renamed to `radix/stdlib/locale/` (E8). The payload ships the current
  `locale/` layout; the resolver targets exactly one layout and the verify step
  pins it.
- **Pack source drift in radix (read-only):** pack bytes and the reference-pack
  assembler may change; the assembly receipt records source commits and the
  manifest pins digests — drift after assembly is a tamper/skew failure, not a
  silent re-read.
- **Schema shape drift while streamline Stage 3 is in flight:** if the two
  deliveries land in either order, the instance must remain valid under the
  documented schema; both specs cross-reference §3/§4/§6 and neither pre-writes
  the other's artifact.
- **Foreign WIP** in `src/package/device/*` (U6-D surface) — untouched; base
  `70cca44` cited for the diff.
- **Site/CLI drift since 2026-08-07 evidence** — date-stamp all claims;
  re-verify anything that would change a resolver decision.
